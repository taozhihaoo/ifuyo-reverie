# Recovery & Doctor — ifuyo Reverie（M10）

> 数据损坏、异常退出、索引丢失、版本升级、库搬迁时的恢复语义与 Doctor 使用说明。
> 架构细节见 docs/M10-STATUS.md / M10-EXPLORE.md。

## 数据归属（谁是可以丢的）

| 数据 | 位置 | 可否丢失 |
|---|---|---|
| 文章正文 article.md / 原始网页 source/ | 库内文档目录 | **绝不能**（真相） |
| EPUB 原文件 books/<id>/book.epub | 库内 | **绝不能**（真相，字节不可变） |
| PDF 原文件 pdf/<id>/document.pdf | 库内 | **绝不能**（真相） |
| 元数据 meta.json / 标注 annotations.jsonl | 库内 | **绝不能**（真相） |
| 订阅 feeds.json / 用户状态 user-state.json | 库内 | **绝不能**（用户资料） |
| 库索引 index.json（REVERIE_HOME） | 派生 | 可丢——自动重建 |
| 搜索索引 search-index.json | 派生 | 可丢——自动重建 |
| 修复日志/备份/隔离区 .recovery/ | 附加 | 可丢（但建议随库备份） |

**整个 Library 文件夹就是全部用户资料**：复制它 = 完整备份；换电脑/换路径 = 直接可用
（重建索引即可），无需携带任何缓存或索引。

## 恢复语义（故障 → 行为）

| 故障 | 行为 |
|---|---|
| 删除索引 index.json | 启动/加载时自动重建；用户数据与状态全部幸存 |
| 索引损坏（坏字节） | 同上——重建，绝不致命报错 |
| 写入中崩溃 | 原子写保证：原文件完好，只剩 `*.tmp-*` 残留（可清扫） |
| 采集中断 | staging `.tmp-<id>` 残留 → Doctor「恢复」（完整→转正；不完整→隔离区） |
| meta.json 损坏 | Doctor 报告该文档不可读；**不覆盖为默认值**（人工处理） |
| annotations.jsonl 坏行 | 读取端跳过并报告；Doctor 可做记录级修复（备份→保留好行→隔离坏行） |
| 未来版本文件 | 只读保护：可读、拒写、Doctor 报 error——升级 Reverie 是唯一恢复路径 |
| 导出中断 | 临时文件残留；重导出即可（临时命名不会伪装成成品） |
| 库移动/换电脑 | 整目录复制 → 全部功能可用（库内路径全相对） |
| 手工修改文件 | 增量刷新吸收变化；标注按 quote/context 重定位，失败→orphaned 不删除 |

## Doctor

- 入口：侧栏「🩺 Doctor 体检」或 `npm run doctor [-- --repair]`。
- **扫描**：11 项检查（存储根 → 文档 → 重复 id → 标注 → 空正文 → 孤儿 tmp →
  staging → 未来版本 → 订阅 → 索引一致性），先文件后索引（索引坏也能跑）。
- **发现**：每条含 checkId / 严重度（info|warning|error|critical）/ 位置 / 问题 /
  可修复性（safe|conditional|manual|none）/ 建议动作。
- **安全修复**：仅 safe 级（清扫 tmp、staging 恢复、重建索引）；执行前预览
  （目标/动作/影响/风险），自动备份，逐项写修复日志，完成后重扫验证。幂等。
- **记录级修复**（标注）：备份原文件 → 保留全部有效行（未知字段保留）→ 坏行/重复行
  移入隔离区 → 刷新搜索索引。
- **隔离与备份**：都在 `<Library>/.recovery/` 下，带时间戳与原因，永不混入正常索引，
  可人工还原。
- **报告导出**：Markdown（元数据与发现，不含正文内容）。

## 修复原则（不可协商）

1. 宁可不修，不能把正确数据修坏。
2. 破坏性操作（删除/覆盖用户文件）默认禁止，Doctor 只报告。
3. 无法可靠修复的标记 unresolved，不伪造"已修复"。
4. 修复前有备份、有日志、有重扫；Doctor 自身失败不产生数据损失。
